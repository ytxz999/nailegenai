# 奶了个奶

一个"三张凑齐就消"的堆叠消除小游戏：点一张**没被压住**的牌，它飞进底部槽位；
同一种奶家角色凑满三张立刻消除；槽位攒满 7 张而这一次没凑成三张，就输了。

纯前端，**双击 `index.html` 就能玩**——没有构建步骤、没有依赖、没有任何网络请求
（三关的牌面素材是同目录下的 16 张 PNG，背景是一张本地油画）。

> **关于名字**：项目原名「叠叠消 / StackMatch」，交付前统一改名为「奶了个奶」。
> 两处技术标识保留旧代号，是有意为之：①`localStorage` 三个键（`nailegenai.save` 等）已随改名更新，
> 但**旧存档不再被读取**，首次打开相当于新局；②代码内部命名空间仍是 `window.SM`（初版代号缩写），
> 全量改名会动到 42 个文件的每一行，风险大于收益。

## 1. 怎么运行

| 方式 | 步骤 | 说明 |
|---|---|---|
| **推荐** | 双击 `index.html` | 用 Chrome / Edge 打开即可。用 `file://` 直接跑是刻意设计（NFR-01） |
| 起本地服务 | `cd nailegenai && python -m http.server 8000` 然后访问 `http://localhost:8000/` | 想换浏览器或调试 CORS 时用 |

> 需要浏览器支持 `localStorage`（存档用）。隐私模式下游戏能玩，但关掉页面后进度不留。
> 首次点击页面才会出声——这是浏览器的策略，不是 bug。

## 2. 玩法

1. 点一张**亮的、没被压住**的牌 → 它飞进底部槽位。
2. 被上面一层压住的牌会压暗，点它会抖一下并发出"不行"的声音，**不算步数**。
3. 槽位里同一种角色凑满 **3 张** → 立刻消除，后面的牌往前补位。
4. 牌堆清空、槽位也空了 → **通关**。
5. 槽位满 **7 张**且这一次点击没凑成三张 → **失败**。

顶部状态栏：关卡 / 剩余 / 步数 / 用时 / 状态，右侧是「设置」与「暂停」。
底部从左到右：**移出暂存区（3 格）**、**槽位（7 格）**、**道具条**。

快捷键：`空格` 暂停 / 继续；`Esc` 关闭当前弹窗。

## 3. 三关难度

| 关卡 | 层 × 列 × 行 | 总张数 | 图标种类 | 每种张数 | 道具（撤销/移出/洗牌） |
|---|---|---|---|---|---|
| 入门 | 4 × 5 × 3 | 60 | 10 | 6 | 3 / 2 / 2 |
| 进阶 | 6 × 6 × 3 | 108 | 12 | 9 | 2 / 1 / 1 |
| 挑战 | 6 × 6 × 4 | 144 | 16 | 9 | 1 / 1 / 1 |

> "层 × 列 × 行"里的 **列 × 行 = 每层张数**（不是外部轮廓）。牌不是按格子铺满的，
> 而是在一块比它大 35% 的栅格里随机挑位置，所以牌堆的四边是毛的、有空隙。

三关**都保证有解**：生成器沿一条合法的"拆除序列"倒着铺牌，每三张一组投同一个图标，
并现场模拟一遍验证槽位峰值不超过 3（`checkSolvable`）。挑战关的"恶意"体现在
图标杂（16 种）、层数深、道具只有 1 次——**难在找到那条通关序列，而不是无解**。

### 牌堆是怎么摆的

每层的张数是固定的（`列 × 行`），但位置是随机挑的，思路参考开源项目
[yulegeyu](https://github.com/liyupi/yulegeyu) 的 `levelBlockNum` / `borderStep`：

1. 候选栅格比"刚好铺满"大 35%（`LevelConfig.GRID_WIDEN`），随机取样 ⇒ 填充率约五成，四边不平整；
2. 越上层的牌越往中间挑（按到中心的距离做拒绝采样）⇒ 底宽上窄，像一座塔，纵深才有出处；
3. 层与层之间错开半格（`shift = layer % 2`）⇒ 上面的牌只压住下面的右下角，边露出来才看得出"压着"；
4. 同层不重叠（格位坐标都是偶数，不同列至少差 2 个半格），所以每张牌最多被上层压住，不会自压。

摆完之后仍然沿一条合法的拆除序列投图标，所以"随机摆放"与"保证有解"不冲突。

三关自由选择，不强制顺序解锁。每关的最佳记录（最短用时，其次最少步数）各留 5 条。

## 4. 道具

| 道具 | 效果 | 备注 |
|---|---|---|
| **撤销** | 退回上一步：牌回到原位、消除的三张回到槽里、道具次数也退回来 | 撤销栈上限 30（写在关卡配置里）；刷新后撤销栈清空，按钮会置灰 |
| **移出** | 把槽位最前面最多 3 张拿出来，放到左侧**暂存区**，给槽位腾地方 | 暂存区的牌**可以点回槽位**；暂存区满 3 张时按钮置灰 |
| **洗牌** | 重排牌堆里**还没消除**的牌的角色，位置与遮挡关系不变 | 整组三张一起换，所以换完仍然可解；洗牌本身也可撤销 |

道具次数用完按钮置灰；一次都不充能（没有内购，哈哈）。

## 5. 存档与记录

三份数据都放在 `localStorage`：

| 键 | 内容 | 何时写 |
|---|---|---|
| `nailegenai.save` | 进行中/暂停的这局（牌面、槽位、暂存区、用时、步数、道具次数） | 每次操作后 300ms 节流；切后台或关页面立刻写 |
| `nailegenai.best` | 三关各自的最佳记录（每关最多 5 条） | 通关时，且**严格更优**才插入 |
| `nailegenai.settings` | 音效 / 降低动效 / 是否看过提示 | 改完立刻写 |

刷新页面会弹「继续上局？」；坏档或版本不符会自动丢弃并提示，不会白屏。
**撤销栈不进存档**——刷新手感骗不了人。

## 6. 演示脚本（照着点，一步一句）

1. **开局**：双击 `index.html`，在选关弹窗点「进入『入门』 60 张」，牌面铺开、计时开始。
2. **点击消除**：点三张同一种角色（例如三只奶狗），它们依次飞进槽位，第三张落下时"凑齐三张"飘出、三张一起消失。
3. **用移出**：点道具条「移出」，槽位最前面的牌被搬到左边暂存区，槽位让出位置。
4. **撤销**：点「撤销」，刚移出的牌回到槽位，移出次数从 1 变回 2。
5. **洗牌**：点「洗牌」，整堆牌被"抄起来"打乱再落回原位，角色全部换过一遍。
6. **通关 / 失败**：一路点到牌堆与槽位都空 → 弹出「通关！」（有暖光与新纪录提示）；
   或者故意连着点 7 张不同角色 → 弹出「失败」，失败不记入最佳记录。

## 7. 目录结构

```
nailegenai/
  index.html              唯一页面：HUD + 舞台 + 道具条 + 暂存区 + 槽位
  README.md               本文件
  assets/nai/*.png        16 个角色牌面（从一张族谱图上切下来的透明 PNG）
  assets/bg-nai.png       对局背景（星月夜风格的奶蛙油画）
  styles/
    base.css              变量与配色（--u:28px 是半格）
    layout.css            HUD / 舞台 / 背景层
    board.css             牌堆与牌面（层级、遮挡、抖动）
    tray.css  holding.css 槽位与暂存区（绝对定位 + left 过渡做"补位"）
    prop.css  modal.css   道具条、弹窗、toast
    animations.css        一次性反馈（飘字 / 回弹 / 脉冲 / 通关暖光）
  src/
    model/                tile icon-set level-config board tray holding
    engine/               event-bus timer level-generator command undo-manager
                          prop-table prop-manager game
    data/                 schema storage-adapter repository levels fixture
    view/                 icon-face slot-strip-view board-view tray-view holding-view
                          hud prop-bar dialogs settings-panel effects renderer input
    audio/sound.js        WebAudio 合成音效（不引入任何音频文件）
    main.js               装配 + 选关/暂停/结算/存档/快捷键
  docs/                   （在仓库根目录的 docs/ 下）需求、分析、设计、计划、交互记录
```

> `prop-table.js` 是道具登记表（kind → 显示名/图标/由哪个 Game 方法执行），
> `slot-strip-view.js` 是槽位与暂存区共用的"定长格子 + 牌浮层"基类。
> 两者的存在理由都写在文件头注释里，是走查后合并重复与消除 if/else 的结果。

四层单向依赖：`model ← engine ← view`，`data` 只搬纯数据；模型层不认识 DOM，
视图层不判断规则。所有脚本用经典 `<script>` 按顺序加载（`file://` 下 ES Module 会被 CORS 拦）。

## 8. 自测与调试

打开页面后，浏览器控制台会打出一份环境报告（关卡表、五条不变式、可点牌数）。
常用命令：

```js
SM.app.game.debugCount()        // 牌堆总数 / 每层 / 每种图标
SM.app.game.assertInvariants()  // 五条不变式（含槽位与暂存区的 3 的倍数）
SM.app.board.pickableIds()      // 现在能点的牌
SM.app.game.useProp('shuffle')  // 手动用一次洗牌
SM.app.game.props.counts()      // 道具剩余次数
SM.app.game.undoStack.types()   // 撤销栈里都有什么
SM.app.repo.loadBest()          // 三关最佳记录
SM.app.sound.play('clear')      // 单独听一个音效
```

## 9. 已知限制

1. **只有三关**，没有无尽模式、没有关卡编辑器。
2. **撤销栈不跨刷新**：存档只存局面，不存操作历史（这是刻意的，见 §5）。
3. **挑战关容错极低**：1 次道具、16 种图标、144 张，正常玩很容易输——它本来就是"给自己找罪受"的那一关。
4. **移动端只是"能玩"**：布局在 720px 以下会换行，但没有做手势与竖屏专门优化。
5. **音效只有开关，没有音量条**；且必须点过页面才会出声（浏览器策略）。
6. **背景图是一张 1.5MB 的油画**，首次加载在慢盘上会有一瞬间空档。
7. **没有排行榜 / 分享 / 账号**，最佳记录只存在本机浏览器里。
8. 三关的牌面素材来自用户提供的表情包图，经脚本切图去背；脚本与切图参数留在仓库里以便复现。
